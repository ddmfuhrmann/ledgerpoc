# /prd

Cria um PRD (Product Requirements Document) e salva no Notion.

Leia `.skills/notion-docs.md` antes de começar.

---

## Quando usar

Antes de planejar uma feature nova de maior escopo, quando precisar alinhar
requisitos funcionais, critérios de aceitação e o que está fora do escopo
antes de entrar no `/plan`.

## Inputs

Peça ao usuário (se não fornecido):
1. **Nome da feature**
2. **Problema** — o que está errado ou faltando, quem é afetado
3. **Objetivo** — o que queremos alcançar (mensurável)
4. **Requisitos funcionais** — lista numerada
5. **Fora do escopo** — o que explicitamente não será feito
6. **Critérios de aceitação** — formato "Dado X, quando Y, então Z"
7. **Perguntas em aberto** — bloqueadores ou incertezas

## Procedure

1. Coletar os inputs acima (pode ser uma conversa, ticket, ou ideia vaga — extraia a intenção).
2. Rascunhar o PRD e apresentar ao usuário para revisão antes de salvar.
3. Após confirmação, criar a página no Notion usando o template PRD em `.skills/notion-docs.md`.
4. Confirmar com o link da página criada.

---

> PRD salvo. Use `/plan` para transformar os requisitos em plano de implementação.
